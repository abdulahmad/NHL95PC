## 2. Verify

```
make              # CBUILD=1 when the compiler is found: matched C replaces its asm
make CBUILD=0     # pure asm build
make cinfo        # says whether CBUILD=1 is available
```

Both builds must end with `MATCH: build/HOCKEY.EXE is byte-identical to the retail HOCKEY.EXE`. If `make cinfo`
says CBUILD=0, fix the compiler setup first.

Fast loop (each C file is one DOSBox run, so avoid rebuilding everything per function):

```
python3 tools/cdiff.py src/c/<seg>/<F>.c   # per function: prints MATCH when the C bytes equal the asm
python3 tools/cverify.py                   # cdiff every marked function in changed C files
make FAST=1                                # incremental; C objects ignore header mtimes
make fullcheck                             # from scratch, CBUILD=1 and CBUILD=0 in parallel (~45 s)
```

CBUILD=1 and CBUILD=0 objects live in separate dirs (build/obj, build/obj0), so switching modes no longer
reassembles everything. Run `make fullcheck` once per commit batch; every pushed commit must have passed it.

**Step 3 (2026-10-20 to 21): tools/permute.py, done.**

* What it does, per function: it applies one transform to the current best text, or two at random once the single ones are used up. The transforms: an integer local's type, swapdecl, movedecl, scope (tools/scope_decls.py), swapstmt, commute, cmpflip, incdec, zero, chain, ternary, temp (inline a one-use local), rettype, paramtype, tempadd (a subexpression into a new int temporary), ifswap and forchain.
* It compiles the candidates in batched DOSBox runs (`cc.compile_parallel`) and scores each with `cdiff.compare()`: the aligned count of differing instructions, then the size difference, then a later first difference. It climbs from the best, with plateau moves.
* It logs every attempt to tools/permute_log.csv (date, func, file, transform chain, sha1 of the function's text, score, sizediff, match, first, cc). A logged candidate is never compiled again under the same compiler (cc is WATCOM_VER; rows from before 2026-10-22 have none and count as 10.0 LA), and logged candidates count toward the stall.
* It stops at a match, 2000 candidates, 30 minutes or 300 candidates without improvement. One search runs at a time (build/permute.lock).
* `--write-match` writes the C file back only on a match; `--write` writes on any improvement. The best variant always goes to build/permute/ under the C file's path.

## 6. Gotchas and learnings

* Never run gen_cheaders.py while `make fullcheck` runs (it wipes build/obj and headers come out with ~46
  labels, breaking every C file). Recovery: copy missing build/obj0/cseg01/*.o into build/obj/cseg01, rerun
  gen_cheaders.py, then make fullcheck.
* FatalError is printf-style: `void __cdecl FatalError(char *msg, ...)`.

* Breadth-pass learnings (2026-10-09): a two-function file with a shared tail works for any `jmp Other.x` /
  `jmp Other_common` (LoadPlayerPhotos -> LoadPhotoBankF_x, DrawSelBoxOff -> DrawSelBox_common); mark the second with
  `cc.py mark FILE.c --func F` and check it with `cdiff.py --func F`. Re-reading a global (regd0.w) instead of
  caching it in a local frees a register (lcfound). A bottom-tested loop with a leading jmp is `for`, a top-tested
  one `while` (resetplstuff). `a = b = 0` chains store right to left (cleargamevars, dword_C5860 = dword_C585C).
  Ternaries inside the call arguments keep the argument registers' load order (LoadPhotoBankF's MakePath).
  Unsolved, seen 3 times: `return 0` emitted as `xor eax,edx` after a compare of two bools
  (ChkDelayedOffside, ChkPullGoalieLate), and `x + 2` / `-x` going to a fresh register (asseben, GetHotStick).

* A register that a function changes without saving it is a parameter (Watcom does not save its own parameter
  registers): releasepl(tm, pl) and holdplayer's edx pass-through were found this way. A pushed / restored edx
  means edx is not a parameter.
* cdiff shows immediates that hold a function address (CalNextMonth storing &CalNextMonth) as mismatches; if that
  is the only difference, mark the file and check with `make FAST=1`. A `mov [abs], imm` with two absolute fixups
  (statsredrawcb and the screen function) is the same false mismatch. The object fixups name both symbols.
* `cdiff.py --func F` finds F in another segment's asm file (TickPanelPenalties in 006, from DrawPanelLine.c in
  005); mark it with `cc.py mark FILE.c --func F --seg STEM`. EasnSkaterStatsScreen's listing is
  misaligned: its `db` swallows the `E8` of `call __CHK`. EasnTeamStatsScreen and EasnGoalieStatsScreen only had
  the opening `push` as `db`; those are real `push dword` instructions now, same bytes, with the symbol address.
* `a = b = c = 0` stores c first, then b, then a.
* Watcom keeps a shared `pop .. ret` epilogue in a function chosen by content, not by source order
  (CmpTeamStandings, LeagueSettingsDlg). Reordering drafts in the C file can move it into the function the
  original used; check where the `ret` lands in the object.
  assrefwhistle.c keeps one `ret` for eleven functions; in address order it lands in assrefwhistle as in the
  EXE, other orders moved it into asswingd or assrefgoalline. Try address order first.
* Watcom does not save a parameter register it overwrites: a function that writes edx without pushing it takes
  a second argument, even an unused one (POHiliteSlot).
* Reusing a parameter for a derived value (`games = games / 2 + 1`) keeps it in its own register from the entry
  copy (`mov ebp, edx; shr ebp, 1; inc ebp`); a new local is computed in place in edx (SeriesWinner).
* A loop that copies until a negative byte (`for (j = 1;; j++) if ((a[j - 1] = a[j]) < 0) break;`) gives the
  original's `jl` out / `inc` / `jmp` back; a for-loop condition puts the test at the bottom (ProcessPenaltyList).
* Two locals the original keeps in one fixed stack order (a path buffer and a struct) can be one struct when
  declaration order does not move them (AddHumanTeam).
* A counter kept in a stack slot although registers are free is a struct field (Watcom does not enregister
  them); a loop with no jump to its test first is a do-while (LoadGameRoster). A function with more than four
  arguments takes the rest on the stack and pops them itself: declare it without __cdecl (ExportTeamToFloppy).
* A menu callback that writes edx without saving it is declared with two (unused) int arguments
  (MenuOpenSaved), as POHiliteSlot's second argument.
* `cc.py frag` resolves a branch into an unmarked draft by the draft's tail bytes, relocated fields as
  wildcards: up to the next `ret`, else up to the first call / jmp out of the module or a `jmp` right after a
  relocated field (assrefdrop into the SkateToSpot tail, asscentero into asswingo_evade).
* A prototype with `unsigned char` parameters makes every call zero-extend its arguments (and here spilled a local
  into an ebp frame). The original setInjuryType passes PostInjuryEvent plain ints: call it through an int-argument
  cast. A loop counter that reuses another local (ChkOffsides' `side` as the do-while count) keeps that register.
* A call the original makes without loading eax (CompactSpeechMem's FindLoadedSpeechSlot, relying on the value
  left in eax) is an argument-less call: `((int (*)(void))FindLoadedSpeechSlot)()`.
* A byte local the original keeps on the stack (`mov [esp], al` ... `mov bl, [esp]`) can be `volatile`
  (updatereplay); that also brings back the frame and the shared epilogue.
* Testing a flag byte twice and then `&= / |=` (asspassrec) matches when written on the field each time with two
  statements, not through a cached local.
* Parameter registers follow how often a parameter is written: `y += a; y += b` swapped the ebp / edi homes of x
  and y; `y = y + a + b` matched DrawMenuItemSel / DrawMenuItemNorm.
* `tools/gen_cheaders.py` reads `build/obj`: never run it while `make fullcheck` runs (fullcheck deletes build/obj and
  the headers come out nearly empty). If that happens: `git checkout` asmfuncs.h / globals.h, delete the asmfuncs.h
  lines of functions newly declared in protos.h, `make`, then rerun gen_cheaders.
* A byte read the 68k way through a dword (`mov edx,[x-3]; sar edx,18h`) is `*(int *)((char *)&x - 3) >> 24` in C
  (SortNonDefPlayers); the same idea as the short `[x-2]` / `sar 10h` loads.
* A parameter register reused for a temp (AdjustFacingDirection: `want = f - want`) means the C reuses the parameter.
* A stride product that strength-reduces to shifts (`tradecursor[side] * 0x16` in DrawTradeRow) ends as `add eax, eax` when that product is computed first and stays in the working register. Computing `side * 0x268` first emits the `imul` too early. The last `* 2` is `lea ecx, [eax+eax]` when the product's home is ecx.
* `return randomd0((n >> 1) + n)` with a `short n` shifts the copy (`cwde` / `sar edx, 1`). Under LA, `t = n; return randomd0((t >> 1) + t)` with `int t` was `movsx edx, ax` / `sar eax, 1` / `add eax, edx` (checkagr); under GA that comes from `n += n >> 1; return randomd0(n);`. The operand order `n + (n >> 1)` adds into edx and then needs `movsx eax, dx`.
* A word compared and then subtracted (`p[0] != q[0]` then `p[0] - q[0]`) is loaded once into cx. Reading the compare through `volatile` leaves `cmp si, [q]` and the subtract re-reads memory (CmpPoints).

Details and examples: [docs/C_MATCHING.md](docs/C_MATCHING.md) "Compiler learnings".
* 10.0 GA `wcc386` with **no options** is the reference compiler (since 2026-10-22; 10.0 LA before, kept as
  `make WATCOM_VER=la`). 10.0a widens 16-bit compares.
* Short globals are read as `mov r32,[x-2] / sar r32,10h` and signed bytes as `[x-3] / sar 18h`: declare the
  real type (`short`, `signed char`) in `vars.h` and the compiler emits the same.
* Register choice follows each variable's savings (its uses and definitions, weighted by loop depth): the highest
  picks first. Declaration, statement and operand order (`a == b` vs `b == a`) matter when they change those
  uses or break a tie; `tools/wccre/regdump.py` shows the order ([docs/WCC_INTERNALS.md](docs/WCC_INTERNALS.md)).
  A local copy vs re-reading a field changes the layout (Setplass); early returns fix block order (Acheck).
* `while (--i != (short)-1)` gives the 16-bit compare `cmp si,-1`; a counter reused across loops keeps its
  register (setpersonel).
* Counted 68k loops: `do { } while (--n != 0)`; `for` always adds a jump to the test.
* Shared tails: Watcom merges identical epilogues across a source file; such functions need one C file in
  address order (cc.py `mark --func`).
* 68k high-byte writes (`st position(a3)`) are `HIBYTE(x) = -1` on the PC (`types.h`).
